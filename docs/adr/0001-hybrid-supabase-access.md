# Keep business writes behind the Avin API while clients use Supabase's data plane

Avin keeps Better Auth, its server API, and Drizzle as the authority for authentication and business mutations: clients send commands to the Avin API, which validates them and persists durable state in PostgreSQL. The `anon` and `authenticated` PostgreSQL roles have no privileges on Avin's `public` tables, sequences, or functions, including through future default privileges, so a browser token cannot become a second business-data API through PostgREST. Committed Messages are published to private order topics through Supabase Broadcast-from-Database; Buyer and Seller browser clients authenticate to those channels with a ten-minute Supabase-compatible JWT issued after Better Auth session validation, use them only for live delivery, and recover missed events from the API. Admin Realtime access remains disabled until it can be scoped to an open Dispute, protected by 2FA, and audited. Clients transfer file bytes to Supabase Storage through narrowly scoped signed URLs issued by the Avin API. This boundary avoids exposing privileged database or Storage credentials while also avoiding a second Avin-owned WebSocket and file-transfer relay.
